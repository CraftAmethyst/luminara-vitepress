# Installation & First Startup

This page is intended for server admins setting up a new server or integrating with an existing modpack. This document currently corresponds to `stable/Trials`: Minecraft `1.20.1`, Forge `47.x`, and Java `17`. Mod metadata in source code requires Minecraft `1.20.1` and specifies Forge `47` and above; for production environments, using Forge version `47.4.22`, verified in current project support policies and release notes, is recommended.

## Preparing the Environment

- 64-bit Java 17; verify that `java -version` reports version 17.
- An independent server directory. Do not install directly inside a client `.minecraft` folder.
- Forge Installer for Minecraft 1.20.1.
- Luminara Mod: Download the build artifact matching your Minecraft and Forge versions from [GitHub Releases](https://github.com/CraftAmethyst/Luminara/releases).

## Getting Luminara Mod

Prioritize binary releases from [GitHub Releases](https://github.com/CraftAmethyst/Luminara/releases). Current `stable/Trials` targets Minecraft `1.20.1`, Forge `47.x`, and Java `17`. After downloading, verify the filename and compatibility matrix in the release notes, then place the mod JAR into the server's `mods/` directory.

If the release page provides SHA-256 checksum files, verify the downloaded file before deployment:

::: code-group

```bash [Linux / macOS]
sha256sum luminara-forge-*.jar
```

```powershell [Windows]
Get-FileHash .\luminara-forge-*.jar -Algorithm SHA256
```

:::

The checksum must match the `.sha256` file provided in the Release.

## Building Mod from Source (Optional)

In the root directory of the Luminara source repository, execute:

```bash
./gradlew assembleForgeMod
```

In Windows PowerShell, Git Bash, or WSL, use `./gradlew` as well; only cmd.exe requires using `gradlew.bat`.

Upon completion, distribution files are located at:

```text
build/distributions/luminara-forge-1.20.1-1.0.15-hotfix.jar
build/distributions/luminara-forge-1.20.1-1.0.15-hotfix.jar.sha256
```

Building requires network access to Maven, Forge, and Gradle dependency repositories. The build artifact is a standard Forge mod JAR and does not require an extra Luminara launcher. Routine deployment does not require compiling from source unless you need to test custom commits or develop features.

## Installing Forge Dedicated Server

1. Download the installer from the [Forge 1.20.1 Download Page](https://files.minecraftforge.net/net/minecraftforge/forge/index_1.20.1.html). Production environments recommend `47.4.22` or the current Forge promotion recommended by the project.
2. Place the installer into a clean empty directory and run:

   ```bash
   java -jar forge-1.20.1-47.4.22-installer.jar --installServer
   ```

   Replace the filename with your actual downloaded Forge version.
3. Before first startup, create `eula.txt` confirming you have read and agreed to the Minecraft EULA:

   ```text
   eula=true
   ```

4. Create `mods` and `plugins` directories (Forge usually creates `mods` automatically):

   ```text
   server/
   ├─ mods/
   ├─ plugins/
   ├─ eula.txt
   ├─ server.properties
   └─ run.bat / run.sh
   ```

5. Place the Luminara mod JAR into `mods/`. Forge mods also go into `mods/`; Bukkit/Spigot plugin JARs go into `plugins/`.
6. Start the server using the startup script generated by Forge. Do not attempt to run the mod directly with `java -jar luminara-*.jar`.

::: tip Existing Modpacks
If you already have a Forge server directory, you do not need to reinstall Forge. Stop the server, make a backup, place the Luminara mod into `mods/` and plugins into `plugins/`, then launch with the modpack's original startup script.
:::

## First Startup Checks

After starting, verify:

1. `luminara.yml` is generated in the root directory.
2. Console outputs Luminara version and Minecraft / Forge / Java compatibility details.
3. Forge mods load properly, and plugins do not trigger `Failed to load plugin` or missing class errors.
4. Once the server outputs `Done (...)`, run `/luminara info` in the console or in-game.

`/luminara` requires permission level 2. `/luminara info` displays Luminara version, Git commit hash, Minecraft / Forge / Java versions, CraftBukkit package name, online players, and JVM memory information. When reporting issues, attach this command's output along with full startup logs.

## Connecting to the Server

The default port is governed by `server-port` in `server.properties`, typically `25565`. If DNS and port forwarding are configured properly, you can connect using:

```text
lum.rimecraft.top
```

The domain name serves purely as a connection address and does not replace port forwarding, firewall rules, or proxy configurations. If you use Velocity, configure the backend per the modern forwarding section in the [Configuration Guide](./config).

## Safe Shutdown and Upgrades

- Use the console `stop` command to shut down the server gracefully, avoiding killing the process which can corrupt world or plugin data.
- Back up the entire server directory before upgrading, particularly `world*`, `mods/`, `plugins/`, `luminara.yml`, and config files.
- Do not reuse worlds, Forge builds, or plugin collections across major Minecraft releases. Test startup and world save/load operations in a clone first.
